# Week 2: IAM & Security Foundations

This week I wrote a policy called `S3UploaderOnly-abhishaisd` that lets a user upload files to my training bucket and download them again, and nothing else. It allows two actions, `s3:PutObject` and `s3:GetObject`, only on the objects inside `my-training-bucket-abhishaisd`. I kept it that small on purpose, because that's what least privilege means: give someone only what they need and nothing more. If this user's keys ever leaked, the worst anyone could do is upload and download files in that one bucket, since they can't delete anything, list what's in the bucket, or touch any other service. The `/*` at the end of the bucket name matters because upload and download work on the objects inside the bucket, not the bucket itself, and without it the policy would look right but still fail with AccessDenied. To test it, I made a separate user called `s3-test-user` with no console access and used its own CLI profile, so I wasn't accidentally using my admin permissions. Uploading a file worked, but `aws s3 ls` and listing the bucket both gave AccessDenied, which is correct because I never gave it permission to list. I also turned on IAM Access Analyzer, which showed 0 active findings.
