# Week 1: Cloud Fundamentals & Account Setup

The root user is the account owner, the email and password I used to sign up for AWS. It can do everything, including closing the account, and its permissions can't be limited, so I only use it for one-time setup like turning on MFA and billing access. An IAM user is a separate login I create inside the account with only the permissions I give it. I made an admin user for my daily work, which means that if its keys ever leak, I can delete them without touching the account itself. Everything I do from the console and the CLI now goes through that IAM user, never through root. I also turned on MFA for the root user, so even a stolen password isn't enough to get in. The Shared Responsibility Model splits the security work between AWS and me. AWS secures the cloud itself, meaning the data centers, hardware and network, and I secure what I put in it, like my passwords, permissions, settings and data. In practice, that means AWS keeps the servers safe, but if I leave a bucket open or share a key, that's on me.
