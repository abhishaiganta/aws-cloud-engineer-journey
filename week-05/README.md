# Week 5: VPC Deep Dive

This week I built a custom VPC called `training-vpc` (`10.0.0.0/16`) with the "VPC and more" wizard. It has two public subnets and two private subnets spread across `us-east-1a` and `us-east-1b`, plus an internet gateway and one NAT gateway in the first public subnet. A subnet is only public because its route table sends `0.0.0.0/0` to the internet gateway, while the private subnets send that traffic to the NAT gateway instead. I launched a bastion host in the first public subnet with a security group that only allows SSH from my IP. To reach a private instance, my laptop connects over the internet to the bastion's public IP, and the internet gateway delivers that traffic into the public subnet. From the bastion, I SSH to the private instance's private IP, and that traffic stays inside the VPC through the local route. The private instance has no public IP, and its security group only allows SSH from the bastion's security group, so nothing on the internet can reach it directly. I used SSH agent forwarding (`ssh -A`) so my key never got copied onto the bastion. When the private instance needs the internet, like for `dnf install`, its traffic goes out through the NAT gateway and internet gateway, but nothing outside can start a connection back in. I reused this same VPC and bastion in Week 6, where I SSHed through the bastion into the private Auto Scaling instances to run the load test.
